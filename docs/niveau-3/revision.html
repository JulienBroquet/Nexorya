Transporter les données

TCP — Transmission Control Protocol

TCP établit une connexion entre deux applications et garantit que toutes les données arrivent, dans l’ordre, en renvoyant ce qui se perd et en ralentissant quand le réseau sature.

  • Ouverture en trois temps — SYN, SYN-ACK, ACK.
  • Chaque octet est numéroté ; le destinataire accuse réception ; ce qui manque est retransmis.
  • La fenêtre limite les données envoyées sans accusé ; le contrôle de congestion ralentit en cas de pertes.
  • Une connexion = 4 valeurs — IP source, port source, IP destination, port destination.

UDP — User Datagram Protocol

UDP envoie des messages sans connexion ni vérification d’arrivée ; c’est rapide et simple, idéal quand une donnée en retard ne sert plus à rien.

  • UDP = ports + longueur + contrôle d’erreur, rien de plus — pas de connexion, pas de retransmission, pas d’ordre.
  • Utilisé pour la voix et la vidéo en direct, le DNS, le DHCP, NTP, et par QUIC (HTTP/3).
  • Pour diagnostiquer UDP, pas de poignée de main à observer — un pare-feu peut le jeter silencieusement.

Noms et adresses automatiques

DNS — Domain Name System

Le DNS est l’annuaire d’Internet — il traduit un nom comme www.exemple.fr en adresse IP, en interrogeant une hiérarchie de serveurs de la racine jusqu’au serveur qui fait autorité.

  • Le poste interroge un résolveur, qui remonte la hiérarchie racine → TLD → domaine et met la réponse en cache.
  • Enregistrements clés — A (IPv4), AAAA (IPv6), CNAME (alias), MX (messagerie), PTR (inverse), TXT, NS.
  • Le TTL fixe la durée du cache — à baisser avant un changement d’adresse.
  • Symptôme typique — le service répond par adresse IP mais pas par nom.

DNS approfondi — DNSSEC, filtrage, redondance et attaques

Le DNS est un point critique — s’il tombe, plus rien ne marche ; s’il ment, les utilisateurs partent au mauvais endroit. On le rend redondant, on le signe (DNSSEC) et on s’en sert pour filtrer les menaces.

  • Toujours au moins deux résolveurs et deux serveurs faisant autorité, sur des sites ou des réseaux différents.
  • DNSSEC prouve que les réponses n’ont pas été falsifiées — il ne les chiffre pas.
  • Chiffrer les requêtes — DoT (TLS) ou DoH (HTTPS) ; cela protège la vie privée, mais peut contourner le DNS de l’entreprise.
  • Le DNS sert aussi de capteur de sécurité — les journaux de requêtes révèlent les machines infectées.

DHCP — Dynamic Host Configuration Protocol

DHCP donne automatiquement à chaque appareil son adresse IP, son masque, sa passerelle et ses serveurs DNS, pour une durée limitée appelée bail.

  • Échange en quatre messages — Discover, Offer, Request, Ack (DORA).
  • Le client reçoit au minimum — adresse, masque, passerelle, DNS, durée du bail.
  • Le DHCP commence par un broadcast — il ne traverse pas les routeurs sans relais (ip helper-address).
  • Adresse en 169.254.x.x = aucun serveur DHCP n’a répondu.

NAT — Network Address Translation

Le NAT remplace les adresses privées d’un réseau par une adresse publique à la sortie vers Internet, et fait le chemin inverse pour les réponses ; toute une entreprise peut ainsi partager une seule adresse publique.

  • Le PAT (NAT avec ports) fait partager une adresse publique à des milliers de machines, en distinguant les connexions par le port.
  • Le routeur garde une table de traduction — les réponses retrouvent ainsi le bon poste.
  • Depuis Internet, on ne peut pas joindre un poste interne sans règle explicite (NAT statique, redirection de port).
  • Le NAT complique les protocoles qui transportent des adresses dans leurs données (SIP, FTP actif).

Le Web et le chiffrement

HTTP — Hypertext Transfer Protocol

HTTP est le langage du Web — le navigateur envoie une requête (une méthode et une adresse), le serveur répond par un code d’état et un contenu.

  • Une requête = méthode (GET, POST…) + chemin + en-têtes (dont Host).
  • Une réponse = code d’état + en-têtes + contenu. 2xx succès, 3xx redirection, 4xx erreur du client, 5xx erreur du serveur.
  • HTTP est sans état — les sessions reposent sur des cookies.
  • HTTP en clair ne doit plus servir qu’à rediriger vers HTTPS.

TLS — Transport Layer Security

TLS chiffre une connexion et prouve au client qu’il parle au bon serveur, grâce à un certificat signé par une autorité de confiance.

  • TLS apporte trois garanties — confidentialité (chiffrement), intégrité (rien n’a été modifié), authentification du serveur (certificat).
  • Le certificat doit être valide — bon nom (SAN), dates correctes, chaîne jusqu’à une autorité de confiance.
  • Une horloge fausse sur le poste ou le serveur suffit à faire échouer TLS.
  • Versions à utiliser — TLS 1.2 et 1.3 ; les versions plus anciennes sont à désactiver.

HTTPS — HTTP protégé par TLS

HTTPS, c’est HTTP transporté dans une connexion TLS, sur le port 443 ; le cadenas du navigateur signifie que la connexion est chiffrée et que le serveur a prouvé son identité.

  • HTTPS = HTTP dans TLS, port 443.
  • Le cadenas garantit — connexion chiffrée et serveur authentifié ; pas que le site soit honnête.
  • On redirige systématiquement HTTP vers HTTPS, et l’on active HSTS.
  • Les certificats publics durent désormais quelques mois — leur renouvellement automatique (ACME) est indispensable.

QUIC — Le transport moderne de HTTP/3

QUIC réunit en un seul protocole, au-dessus d’UDP, ce que faisaient TCP et TLS — connexion fiable, chiffrement, flux multiples — avec des connexions plus rapides à établir.

  • QUIC fonctionne sur UDP 443 et chiffre presque tout, y compris ses en-têtes de contrôle.
  • Plusieurs flux indépendants — une perte ne bloque que le flux concerné.
  • Une connexion survit à un changement de réseau (Wi-Fi → 4G).
  • Si UDP 443 est bloqué, les navigateurs reviennent à TCP — c’est pourquoi certains réseaux le bloquent volontairement.

DoT — DNS over TLS

DoT chiffre les requêtes DNS dans une connexion TLS dédiée, sur le port 853 ; personne sur le chemin ne peut lire ni modifier les noms demandés.

  • DoT chiffre les requêtes DNS sur un port dédié, 853 — facile à identifier et à filtrer.
  • Il protège la confidentialité des requêtes ; DNSSEC protège l’authenticité des réponses — les deux sont complémentaires.
  • En entreprise, on l’utilise surtout entre le résolveur interne et Internet, pas depuis chaque poste.

Proxy et répartiteur de charge — Proxy, reverse proxy et load balancer

Un proxy fait les requêtes à la place des postes pour les contrôler ; un reverse proxy reçoit les requêtes à la place des serveurs pour les protéger et répartir la charge entre eux.

  • Proxy (direct) — côté utilisateurs, il sort sur Internet à leur place (filtrage, journalisation, cache).
  • Reverse proxy — côté serveurs, il reçoit les requêtes d’Internet et les transmet aux serveurs internes.
  • Un load balancer répartit les requêtes entre plusieurs serveurs et retire ceux qui ne répondent plus (sondes de santé).
  • Derrière un reverse proxy, le serveur voit l’adresse du proxy — l’adresse du client est dans X-Forwarded-For.

Administrer et superviser

SSH — Secure Shell

SSH ouvre une session chiffrée vers un serveur ou un équipement réseau pour l’administrer à distance, en remplaçant Telnet qui faisait tout passer en clair.

  • SSH chiffre la session et le mot de passe ; Telnet envoie tout en clair et doit être désactivé.
  • À la première connexion, le client mémorise l’empreinte du serveur — un changement inattendu doit alerter.
  • L’authentification par clé est plus sûre que par mot de passe.
  • Sur un équipement réseau — SSH v2, accès limité aux réseaux d’administration, comptes nominatifs.

RDP — Remote Desktop Protocol

RDP affiche à distance le bureau d’un ordinateur Windows et transmet clavier et souris ; c’est l’outil courant du support et de l’administration des serveurs Windows.

  • RDP utilise le port 3389 (TCP, et UDP pour de meilleures performances).
  • Il ne faut jamais exposer RDP directement sur Internet — passer par un VPN ou une passerelle RD avec MFA.
  • NLA exige l’authentification avant d’ouvrir la session graphique.

NTP — Network Time Protocol

NTP garde toutes les horloges du réseau à l’heure, à quelques millisecondes près, en les synchronisant sur des sources de temps fiables.

  • Une heure fausse casse — les certificats (TLS), Kerberos (ouverture de session Windows, tolérance de 5 minutes), la corrélation des journaux.
  • Les sources sont organisées en strates — strate 1 = directement reliée à une horloge de référence.
  • En entreprise, quelques serveurs NTP internes synchronisés sur plusieurs sources ; tous les équipements se synchronisent sur eux.

SNMP — Simple Network Management Protocol

SNMP permet à un outil de supervision d’interroger les équipements réseau (débit des interfaces, état, température…) et de recevoir leurs alertes.

  • Le superviseur interroge les agents (UDP 161) ; les agents envoient des traps (UDP 162).
  • Chaque valeur a une adresse, l’OID, rangée dans une MIB.
  • Utiliser SNMPv3 (authentification et chiffrement) ; v1/v2c reposent sur une « communauté » en clair.
  • Le débit d’une interface se calcule à partir de compteurs qui augmentent — deux mesures et une soustraction.

Syslog — Journalisation centralisée

Syslog envoie les messages des équipements (une interface tombe, un utilisateur se connecte, une règle bloque un flux) vers un serveur central, où l’on peut les conserver, les chercher et les corréler.

  • Chaque message a une gravité de 0 (urgence) à 7 (débogage).
  • Centraliser les journaux protège la preuve — un équipement compromis ou redémarré peut perdre les siens.
  • Sans NTP, les horodatages ne sont pas comparables.
  • Format Cisco — %INSTALLATION-GRAVITÉ-MNÉMONIQUE: message.

Démontrer une panne — Les outils de diagnostic Windows et Linux

Pour dépanner vite, on remonte les couches avec une poignée d’outils — adresse, voisin, route, nom, port, application — et l’on garde la preuve de chaque étape.

  • L’ordre — adresse (ipconfig / ip a) → voisin (arp / ip neigh) → route (route print / ip route) → nom (nslookup / dig) → port (Test-NetConnection / nc) → application (curl).
  • Toujours comparer avec un poste qui fonctionne.
  • Une capture (Wireshark, tcpdump) tranche les débats — elle montre ce qui part et ce qui revient.
  • Noter la preuve de chaque étape — sortie de commande, heure, poste, destination.

Transférer, partager, s’identifier

FTP — File Transfer Protocol

FTP transfère des fichiers avec deux connexions — une pour les commandes, une pour les données ; ancien et non chiffré, il est remplacé par SFTP ou HTTPS.

  • Deux connexions — contrôle (TCP 21) et données (port négocié).
  • Mode actif — le serveur se connecte au client (gêné par le NAT et les pare-feu) ; mode passif — le client se connecte au serveur.
  • Tout circule en clair, mot de passe compris — préférer SFTP ou FTPS.

TFTP — Trivial File Transfer Protocol

TFTP est un transfert de fichiers minimal, sans authentification, sur UDP ; il sert à démarrer des équipements par le réseau et à charger des configurations ou des micrologiciels.

  • Aucune authentification, aucun chiffrement — à réserver à des réseaux maîtrisés.
  • Usages — démarrage réseau (PXE), téléphones IP, sauvegarde et chargement de configurations et d’images.
  • Le transfert continue sur un port différent du port 69 — les pare-feu sans inspection le bloquent.

SFTP — SSH File Transfer Protocol

SFTP transfère des fichiers à l’intérieur d’une session SSH — tout est chiffré, et un seul port (22) suffit.

  • SFTP n’a rien à voir avec FTP — c’est un sous-système de SSH.
  • Un seul port (22), tout est chiffré, authentification par mot de passe ou par clé.
  • Le bon remplaçant de FTP pour les échanges de fichiers entre systèmes ou avec des partenaires.

SMB — Server Message Block

SMB est le protocole des partages de fichiers et d’imprimantes Windows — les lecteurs réseau comme `\\serveur\partage` reposent sur lui.

  • SMB fonctionne sur TCP 445.
  • Utiliser SMB 3 (chiffrement, signature) ; SMB 1 est obsolète et doit être désactivé.
  • Ne jamais exposer le port 445 sur Internet.
  • Les droits combinent les autorisations du partage et celles du système de fichiers (NTFS).

NFS — Network File System

NFS permet à des machines Linux et Unix de monter un dossier distant comme s’il était local ; c’est le partage de fichiers des serveurs et du stockage.

  • NFSv4 n’utilise qu’un port, TCP 2049 ; les versions anciennes en utilisaient plusieurs, dynamiques.
  • Les droits reposent sur les identifiants numériques (UID/GID) — ils doivent correspondre entre client et serveur.
  • Sans Kerberos, NFS fait confiance à l’adresse du client — on le limite à des réseaux dédiés.

LDAP — Lightweight Directory Access Protocol

LDAP permet aux applications d’interroger l’annuaire de l’entreprise — comptes, groupes, ordinateurs — pour authentifier les utilisateurs et vérifier leurs droits.

  • L’annuaire est un arbre d’objets, chacun identifié par un DN (CN=Alice,OU=Compta,DC=exemple,DC=fr).
  • Une application se lie (bind) à l’annuaire, cherche un utilisateur, vérifie ses groupes.
  • Toujours chiffrer — LDAPS (636) ou StartTLS ; un bind simple sur 389 transmet le mot de passe en clair.
  • Active Directory est l’annuaire le plus répandu ; il parle LDAP.

Voix et mobilité

SIP — Session Initiation Protocol

SIP sert à établir, modifier et terminer les appels en voix sur IP — il fait sonner le téléphone et négocie le format audio, mais ne transporte pas la voix elle-même.

  • SIP signale l’appel (INVITE, 180 Ringing, 200 OK, ACK, BYE) ; la voix passe par RTP, sur d’autres ports.
  • La description du média (SDP) annonce l’adresse IP, les ports et les codecs — le NAT la rend souvent fausse.
  • Symptôme classique — l’appel s’établit mais pas de son (ou son dans un seul sens).

RTP — Real-time Transport Protocol

RTP transporte la voix et la vidéo en temps réel sur UDP ; il numérote et horodate chaque paquet pour que le récepteur détecte les pertes et restitue le son au bon rythme.

  • RTP ajoute un numéro de séquence (pertes) et un horodatage (rythme) à chaque paquet média.
  • Un paquet de voix toutes les 20 ms — environ 50 paquets par seconde et par sens.
  • RTCP remonte des statistiques — pertes, gigue, délai.
  • SRTP chiffre le média.

La téléphonie sur IP — Construire un réseau qui transporte bien la voix

Un réseau prêt pour la voix met les téléphones dans un VLAN dédié, les alimente en PoE, leur donne la priorité absolue et surveille latence, gigue et pertes.

  • VLAN voix dédié, annoncé au téléphone par CDP ou LLDP-MED ; le PC se branche derrière le téléphone.
  • PoE pour alimenter les postes, avec un budget dimensionné.
  • QoS de bout en bout — voix marquée EF, file prioritaire, sur tous les liens où elle peut être congestionnée.
  • Objectifs — latence < 150 ms (un sens), gigue < 30 ms, pertes < 1 %.

Wi-Fi d’entreprise — Contrôleur, VLAN et itinérance

En entreprise, des dizaines de bornes sont pilotées par un contrôleur ; chaque SSID est relié à un VLAN, et les appareils passent d’une borne à l’autre sans couper leurs appels grâce à l’itinérance rapide.

  • Un contrôleur (physique ou dans le cloud) configure toutes les bornes, gère les canaux et les puissances.
  • Chaque SSID correspond à un VLAN (employés, invités, objets connectés).
  • C’est le client qui décide de changer de borne ; 802.11k/v l’aident à choisir, 802.11r accélère le passage.
  • Objectif de couverture pour la voix — -67 dBm minimum partout, avec recouvrement entre bornes.
