802.1X

Contrôle d’accès par port

Avec 802.1X, une prise réseau ou un réseau Wi-Fi reste fermé tant que l’appareil n’a pas prouvé son identité ; le serveur décide ensuite dans quel VLAN il entre.

Couche OSI 2Découvrir : 10 minApprofondir : 20 minAvant : RADIUS, VLAN

Commence par « Découvrir ». Passe à « Approfondir » quand l’essentiel est clair.

Le problème : n’importe qui peut se brancher

Dans une salle de réunion, un visiteur branche son ordinateur sur la prise murale : il obtient une adresse et accède au réseau interne. Un attaquant peut faire de même avec un petit boîtier caché sous un bureau. Une prise réseau ouverte, c’est une porte d’entrée sans serrure.

L’idée en une phrase

802.1X met une serrure sur chaque prise : le port reste fermé jusqu’à ce que l’appareil prouve son identité auprès d’un serveur, qui décide ensuite où il a le droit d’aller.

Les trois acteurs

  1. Le poste se branche ; le port est fermé à tout sauf aux messages d’authentification.
  2. Le switch demande l’identité du poste et relaie l’échange vers le serveur RADIUS. Il ne vérifie rien lui-même.
  3. Le serveur vérifie (mot de passe, ou mieux, certificat) et répond « accepté, VLAN 10 » ou « refusé ».
  4. Le switch ouvre le port dans le bon VLAN, ou le laisse fermé.

Et les imprimantes ?

Une imprimante, une caméra ou un vieux badgeur ne savent souvent pas faire 802.1X. On utilise alors MAB (MAC Authentication Bypass) : le switch envoie l’adresse MAC de l’appareil au serveur RADIUS comme identifiant. C’est plus faible (une adresse MAC se copie facilement), donc on donne à ces appareils des droits très limités (un VLAN dédié, une ACL stricte), et l’on complète par du profilage.

Les mots à connaître

  • 802.1X — Norme de contrôle d’accès par port, qui exige une authentification avant d’ouvrir l’accès au réseau.
  • Demandeur — Logiciel du poste qui réalise l’authentification ; supplicant.
  • Authentificateur — Switch ou borne qui relaie l’authentification et ouvre ou ferme l’accès.
  • EAPoL — Transport des messages EAP sur Ethernet ou Wi-Fi, entre le poste et l’authentificateur.
  • MAB — Authentification d’un appareil par son adresse MAC, pour ceux qui ne gèrent pas 802.1X.

Teste-toi

Un visiteur branche son ordinateur personnel sur une prise protégée par 802.1X. Que se passe-t-il ?

Voir le corrigé

Son ordinateur n’a ni identifiants ni certificat de l’entreprise : l’authentification échoue (ou n’a même pas lieu). Selon la politique, le port reste fermé ou le place dans un VLAN invités qui ne donne accès qu’à Internet.

Configuration type d’un port d’accès (Cisco IOS-XE, mode classique)

dot1x system-auth-control
!
interface GigabitEthernet1/0/5
 switchport mode access
 switchport access vlan 999                 ! VLAN sans accès tant que rien n'est autorisé
 switchport voice vlan 20
 authentication host-mode multi-domain      ! un téléphone + un PC
 authentication order dot1x mab
 authentication priority dot1x mab
 authentication port-control auto
 authentication periodic
 authentication timer reauthenticate server
 authentication event server dead action authorize vlan 10   ! VLAN critique si RADIUS est hors service
 authentication event server alive action reinitialize
 mab
 dot1x pae authenticator
 dot1x timeout tx-period 7
 spanning-tree portfast
  • host-mode multi-domain : un appareil dans le domaine voix (téléphone) et un dans le domaine données (PC).
  • order dot1x mab : essayer 802.1X, puis MAB si l’appareil ne répond pas.
  • server dead action : si aucun serveur RADIUS ne répond, autoriser dans un VLAN de secours plutôt que de bloquer tout l’étage.

Sur les versions récentes (IBNS 2.0), la même logique s’écrit avec des politiques (policy-map type control subscriber), plus souples.

Déployer sans tout casser : le mode surveillance

Activer 802.1X en mode bloquant d’un coup provoque des pannes partout (postes mal configurés, imprimantes oubliées). On procède par étapes :

  1. Mode surveillance (monitor mode, access-session open) : le port reste ouvert, les authentifications ont lieu et sont journalisées. On corrige les échecs.
  2. Mode à impact limité : ouvert, mais avec une ACL qui ne laisse passer que l’essentiel (DHCP, DNS, PXE) avant l’authentification.
  3. Mode fermé : seul EAP passe avant l’authentification.

Vérification

SW1# show access-session interface Gi1/0/5 details
            Interface:  GigabitEthernet1/0/5
          MAC Address:  3c22.fb1a.097e
            User-Name:  host/PC-COMPTA-12.exemple.fr
               Status:  Authorized
               Domain:  DATA
       Current Policy:  POLICY_Gi1/0/5
    Server Policies:
            Vlan Group:  Vlan: 10
    Method status list:
       Method           State
       dot1x            Authc Success

host/PC-COMPTA-12… : c’est la machine qui s’est authentifiée (certificat machine), avant même l’ouverture de session de l’utilisateur. C’est ce qui permet aux postes de joindre le domaine et de recevoir leurs mises à jour la nuit.

Limites à connaître

  • Un attaquant peut se placer entre un poste authentifié et le switch (petit switch ou boîtier transparent) et profiter du port ouvert. MACsec (chiffrement du lien) ou le mode single-host/multi-auth limitent ce risque.
  • MAB repose sur une adresse MAC facile à usurper : profilage et ACL strictes sont indispensables.

Exercices

1. Après le passage en mode fermé, les imprimantes d’un étage n’impriment plus. Elles ne gèrent pas 802.1X. Que manque-t-il ?

Voir le corrigé

MAB (et sa règle sur le serveur RADIUS) : les adresses MAC des imprimantes doivent être connues du serveur (liste, ou profilage) et associées à un VLAN ou une ACL adaptée. Il faut aussi authentication order dot1x mab sur les ports, et éventuellement réduire le délai avant MAB (tx-period).

2. Les postes s’authentifient correctement, mais le premier démarrage le matin est très long et les scripts d’ouverture de session échouent. Quelle hypothèse ?

Voir le corrigé

Seule l’authentification utilisateur est configurée : tant que personne n’a ouvert de session, le port reste fermé et le poste ne peut joindre ni le domaine ni le serveur DHCP. Activer l’authentification machine (certificat de l’ordinateur) pour que le port s’ouvre dès le démarrage.
