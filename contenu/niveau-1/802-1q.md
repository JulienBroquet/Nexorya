## Le problème : plusieurs VLAN, un seul câble

Deux switches d’étage portent chacun les VLAN 10 (employés), 20 (téléphones) et 30 (invités). Faut-il trois câbles entre eux, un par VLAN ? Et avec 50 VLAN, 50 câbles ? Évidemment non : on utilise **un seul lien**, qui transporte tous les VLAN. Mais alors, comment le switch qui reçoit une trame sait-il à quel VLAN elle appartient ?

> [!IMPORTANT] L’idée en une phrase
> Sur un lien **trunk**, le switch qui émet glisse dans chaque trame une **étiquette** portant le numéro de VLAN. Le switch qui reçoit lit l’étiquette, la retire et range la trame dans le bon VLAN.

## Comment ça marche

```sequence
titre: Une trame du VLAN 20 traverse un trunk
Téléphone | SW1 | SW2 | Serveur d’appels
Téléphone -> SW1 : trame (port d’accès voix, VLAN 20)
note SW1 : ajoute l’étiquette « VLAN 20 »
SW1 -> SW2 : trame étiquetée VLAN 20 sur le trunk
note SW2 : lit « VLAN 20 », retire l’étiquette
SW2 -> Serveur d’appels : trame normale, dans le VLAN 20
```

- Les **appareils finaux** (PC, imprimantes) ne voient jamais d’étiquette : les ports d’accès les retirent.
- Les **trunks** relient des équipements qui comprennent les étiquettes : switches, routeurs, serveurs de virtualisation, bornes Wi-Fi.

## Le VLAN natif : l’exception sans étiquette

Sur un trunk, **un** VLAN voyage sans étiquette : c’est le **VLAN natif** (le VLAN 1 par défaut). Toute trame reçue **sans** étiquette sur un trunk est rangée dans le VLAN natif.

Conséquence : les deux extrémités doivent avoir **le même VLAN natif**. Sinon, une trame non étiquetée envoyée dans le VLAN 1 d’un côté arrive dans le VLAN 99 de l’autre : les deux réseaux se mélangent.

## Exemple : le VLAN qui ne passe pas

Entre SW1 et SW2, le VLAN 10 fonctionne mais pas le VLAN 20. Sur SW1, `show interfaces trunk` affiche :

```text
Port        Vlans allowed on trunk
Gi1/0/48    10,30
```

Le VLAN 20 n’est pas dans la **liste des VLAN autorisés** sur le trunk. La correction :

```cisco
interface GigabitEthernet1/0/48
 switchport trunk allowed vlan add 20
```

> [!WARNING]
> Sans le mot `add`, la commande `switchport trunk allowed vlan 20` **remplace** toute la liste par « 20 » : les VLAN 10 et 30 sont coupés immédiatement. C’est l’une des erreurs les plus classiques en production.

## Les mots à connaître

- **802.1Q** — Norme IEEE qui définit l’étiquette de VLAN insérée dans les trames sur un trunk.
- **Étiquette (tag)** — Champ de 4 octets ajouté à une trame pour indiquer son VLAN.
- **VLAN natif** — VLAN dont les trames circulent sans étiquette sur un trunk.
- **Liste des VLAN autorisés** — VLAN qu’un trunk accepte de transporter.

## Teste-toi

**1.** Un PC reçoit-il des trames étiquetées 802.1Q ?

<details><summary>Voir le corrigé</summary>

**Non**, en général. Il est branché sur un port d’accès, qui retire l’étiquette. Seuls les équipements reliés par un trunk (switches, routeurs, hyperviseurs) voient les étiquettes.

</details>

**2.** SW1 a le VLAN natif 1, SW2 le VLAN natif 99 sur le même trunk. Quel risque ?

<details><summary>Voir le corrigé</summary>

Les trames non étiquetées passent **du VLAN 1 d’un côté au VLAN 99 de l’autre** : une fuite entre deux réseaux qui devraient être séparés. Les switches Cisco signalent l’incohérence avec le message `%CDP-4-NATIVE_VLAN_MISMATCH`.

</details>

## Format de l’étiquette

L’étiquette s’insère **entre l’adresse MAC source et le type** :

```text
┌──────────┬──────────┬──────────────────────────────┬────────┬─────────┬─────┐
│ MAC dest │ MAC src  │ Étiquette 802.1Q (4 octets)   │ Type   │ Données │ FCS │
└──────────┴──────────┼──────────┬─────┬─────┬───────┼────────┴─────────┴─────┘
                      │ TPID     │ PCP │ DEI │ VID   │
                      │ 0x8100   │ 3 b │ 1 b │ 12 b  │
                      │ 16 bits  │     │     │       │
                      └──────────┴─────┴─────┴───────┘
```

- **TPID** (`0x8100`) : signale qu’une étiquette suit. Il occupe la place où un récepteur s’attendrait à trouver l’EtherType.
- **PCP** (*Priority Code Point*, 3 bits) : priorité de 0 à 7, aussi appelée **CoS**. Les téléphones IP marquent souvent 5 pour la voix.
- **DEI** (1 bit) : indique qu’une trame peut être jetée en priorité en cas de congestion.
- **VID** (12 bits) : numéro de VLAN, de 1 à 4094.

L’étiquette ajoute 4 octets : la trame maximale passe de 1 518 à **1 522 octets**. Le FCS est recalculé à l’insertion et au retrait de l’étiquette.

## Configurer un trunk (Cisco IOS)

```cisco
interface GigabitEthernet1/0/48
 description Uplink vers DIST1 Gi1/0/3
 switchport trunk encapsulation dot1q    ! seulement sur les plateformes qui proposent aussi ISL
 switchport mode trunk
 switchport nonegotiate                  ! pas de DTP
 switchport trunk native vlan 999        ! VLAN natif inutilisé, identique des deux côtés
 switchport trunk allowed vlan 10,20,30,99
!
vlan dot1q tag native                    ! option globale : étiqueter aussi le VLAN natif
```

Bonnes pratiques :

- **Limiter** les VLAN autorisés à ceux qui sont nécessaires : un VLAN inutile sur un trunk étend inutilement son domaine de diffusion (et son arbre STP).
- Choisir un **VLAN natif inutilisé** (999), différent du VLAN 1, et identique aux deux extrémités.
- **Désactiver la négociation** (DTP) sur les trunks et les ports d’accès.

## Vérifier : `show interfaces trunk`

```cisco
SW1# show interfaces trunk

Port        Mode         Encapsulation  Status        Native vlan
Gi1/0/48    on           802.1q         trunking      999

Port        Vlans allowed on trunk
Gi1/0/48    10,20,30,99

Port        Vlans allowed and active in management domain
Gi1/0/48    10,20,30,99

Port        Vlans in spanning tree forwarding state and not pruned
Gi1/0/48    10,30,99
```

Lis les quatre blocs **dans l’ordre** : c’est un entonnoir.

| Bloc | Question | Ici |
|---|---|---|
| 1 | Le port est-il en trunk, avec quel VLAN natif ? | oui, natif 999 |
| 2 | Quels VLAN sont autorisés ? | 10, 20, 30, 99 |
| 3 | Parmi eux, lesquels **existent** sur ce switch ? | tous |
| 4 | Parmi eux, lesquels sont **en forwarding** (non bloqués par STP, non élagués) ? | le VLAN 20 manque |

Le VLAN 20 est autorisé et existe, mais il n’est pas en forwarding sur ce lien : STP le bloque (chemin redondant ailleurs ?) ou il est élagué par VTP. On poursuit avec `show spanning-tree vlan 20`.

## Le saut de VLAN (VLAN hopping)

Deux attaques exploitent les trunks mal configurés :

| Attaque | Principe | Parade |
|---|---|---|
| **Usurpation de switch** | Le PC de l’attaquant négocie un trunk via DTP et reçoit tous les VLAN. | `switchport mode access` sur tous les ports utilisateurs, `switchport nonegotiate`. |
| **Double étiquetage** | L’attaquant, dans le VLAN natif, envoie une trame avec deux étiquettes. Le premier switch retire la première (VLAN natif) et transmet ; le suivant lit la seconde et la livre dans un autre VLAN. Attaque à sens unique. | VLAN natif **inutilisé** par les utilisateurs, ou étiquetage du VLAN natif (`vlan dot1q tag native`). |

## Exercices

**1.** Un administrateur tape `switchport trunk allowed vlan 40` pour ajouter le VLAN 40 à un trunk qui portait les VLAN 10 à 30. Conséquence, et comment réparer ?

<details><summary>Voir le corrigé</summary>

La liste est **remplacée** : le trunk ne transporte plus que le VLAN 40, les VLAN 10 à 30 sont coupés. Réparer : `switchport trunk allowed vlan 10-30,40` (ou `add 10-30`). Pour éviter l’erreur : toujours `add` et `remove`, et vérifier avec `show interfaces trunk` avant et après.

</details>

**2.** Calcule la taille maximale d’une trame étiquetée portant 1 500 octets de données.

<details><summary>Voir le corrigé</summary>

6 (MAC dest) + 6 (MAC src) + 4 (étiquette) + 2 (type) + 1 500 (données) + 4 (FCS) = **1 522 octets**. Un équipement qui refuse les trames de plus de 1 518 octets les compterait comme « giants ».

</details>

**3.** Le VLAN 30 apparaît dans les trois premiers blocs de `show interfaces trunk`, mais pas dans le quatrième, sur un seul des deux uplinks d’un switch d’accès. Est-ce forcément un problème ?

<details><summary>Voir le corrigé</summary>

**Pas forcément.** Si le switch a deux uplinks vers deux switches de distribution, STP bloque normalement le VLAN 30 sur l’un d’eux pour éviter une boucle. C’est un problème seulement si le VLAN 30 n’est en forwarding **sur aucun** uplink, ou si le blocage est inattendu au regard du design (racine mal placée).

</details>
